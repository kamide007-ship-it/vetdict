# VetDict プロフェッショナル評価レポート

**対象**: VetDict v5.0.0 — 多動物種対応 獣医学疾患データベース
**評価日**: 2026-03-16
**評価観点**: 獣医師・アナリスト・マーケーター・エンジニア

---

## 1. 獣医師（Veterinarian）の視点

### 総合評価: ★★★★☆（4.0 / 5.0）

### 強み

- **網羅性が非常に高い**: 20種の動物種、4,800以上の疾患、175以上の薬剤を収録。犬猫だけでなく、エキゾチック動物（ハリネズミ、デグー、シュガーグライダー等）まで対応している点は、国内外の既存ツールと比較しても突出している。
- **鑑別診断エンジンの実用性**: 症状チェックボックス方式による鑑別診断は、臨床現場での使い勝手が良い。Jaccard類似度によるスコアリングは統計的に妥当なアプローチ。
- **薬剤辞書の充実**: 種別の用量、投与経路、薬物相互作用、禁忌まで含む薬剤データベースは、日常診療で即座に参照可能。Plumb's、BSAVA等の信頼性の高いリファレンスに基づいている。
- **日英バイリンガル対応**: 日本の獣医師が英語文献を参照しつつ日本語で使える環境は非常に有用。
- **獣医師法への配慮**: 法的免責事項を明示し、「診断支援ツール」としての位置づけを明確にしている。

### 改善提案

| 項目 | 詳細 |
|------|------|
| **画像診断の統合** | X線・超音波・CT画像の参考所見をデータベースに追加すると、鑑別診断の精度が向上する |
| **臨床パスウェイ** | 疾患ごとに推奨検査フロー（CBC→生化学→画像→特殊検査）を提示する機能があると実用的 |
| **症例データベース** | 匿名化された実症例の蓄積・共有機能により、データの質が継続的に向上する |
| **EBM情報の付与** | 各疾患・治療法のエビデンスレベル（I〜V）を明示すると信頼性が向上 |
| **疫学データ連携** | 地域別・季節別の疾患発生頻度データを統合すると、鑑別診断の優先順位がより臨床的に適切になる |

### 臨床的リスク評価

- RECO2/RECO3によるAI安全層は、過信防止・曖昧性検出の観点で優れている
- ただし、緊急症例（GDV、DKA等）のトリアージ優先度表示機能の追加が望まれる
- 「この疾患を見逃してはいけない」というRed Flag表示があると安全性が向上する

## 2. アナリスト（Analyst）の視点

### 総合評価: ★★★★☆（4.2 / 5.0）

### データアーキテクチャ評価

| 指標 | 評価 | コメント |
|------|------|---------|
| **データ量** | ◎ | 4,800疾患 × 20種。diseases_all_species.json（12MB）は十分な規模 |
| **データ構造** | ○ | JSON + Pythonモジュール。スキーマは一貫しているが、正規化の余地あり |
| **検索性能** | ○ | Jaccard類似度ベースのマッチング。O(n)スキャンだが現実的なデータ量では十分 |
| **品質管理** | ◎ | content_quality.pyによるバリデーション、Phase別エンリッチメントパイプライン |
| **拡張性** | △ | RDBMSへの移行が将来的に必要。現在のファイルベースは10,000疾患超で限界の可能性 |

### データ戦略提案

1. **構造化データベースへの移行**: PostgreSQL + JSONBカラムにより、クエリ性能と柔軟性を両立
2. **分析基盤の構築**: 利用ログの構造化収集（種別・症状・結果の組み合わせ）→ 疾患トレンド分析
3. **A/Bテスト基盤**: 診断アルゴリズムの改善を定量的に検証する仕組み
4. **データパイプライン自動化**: 新文献からの疾患情報抽出を半自動化（現在のAIエンリッチメントの発展）

### 競合分析フレームワーク

|------|------|--------|------|---------------|--------|
| **VetDict** | **20** | **4,800+** | **175+** | **Yes** | **Yes** |
| VetCompass | 限定 | 統計中心 | No | No | No |

## 3. マーケーター（Marketer）の視点

### 総合評価: ★★★☆☆（3.5 / 5.0）

### ポジショニング分析

**現在のUSP（Unique Selling Proposition）**:
> 「世界最大のオープンソース獣医学鑑別診断プラットフォーム」

これは技術者には響くが、エンドユーザー（獣医師）には「オープンソース」の訴求力が弱い。

**推奨リポジショニング**:
> 「20種4,800疾患を瞬時に鑑別 — 獣医師のための臨床意思決定支援ツール」

### ターゲットセグメント戦略

```
        [収益ポテンシャル]
高  │  ② 動物病院チェーン    ① 大学・教育機関
    │    (組織導入)            (教材・研修)
    │
    │  ③ フリーランス獣医     ④ ペットオーナー
低  │    (個人利用)            (健康参考)
    └──────────────────────────────
       低                      高
              [市場規模]
```

**優先ターゲット**: ① 大学・教育機関 → ② 動物病院チェーン

### GTM（Go-To-Market）戦略

| フェーズ | 施策 | KPI |
|----------|------|-----|
| **Phase 1: 認知** | 獣医学会での発表・デモ、学術論文投稿 | 学会参加者認知率 |
| **Phase 2: 獲得** | 獣医大学との提携、無料ワークショップ | 登録ユーザー数 |
| **Phase 3: 活性化** | 臨床現場フィードバックループ、コンテンツ拡充 | MAU・継続率 |
| **Phase 4: 収益化** | プレミアム機能（AI診断チャット、API連携） | MRR |

### ブランド・UI評価

| 項目 | 評価 | コメント |
|------|------|---------|
| **ロゴ・VI** | ○ | Navy × Green のカラーパレットは信頼性と専門性を表現 |
| **ランディングページ** | ○ | ヒーローセクションの統計表示は説得力がある |
| **CTA設計** | △ | 「診断を開始」ボタンの配置・デザインをより目立たせるべき |
| **ソーシャルプルーフ** | ✕ | ユーザーの声・導入事例が不在。信頼構築に必須 |
| **SEO** | △ | メタデータ、構造化データ（Schema.org VeterinaryClinic）の追加が必要 |
| **コンテンツマーケティング** | ✕ | ブログ・症例解説等の継続的コンテンツが不在 |

### マーケティング改善の優先順位

1. **ユーザー事例・テスティモニアル**: 実際の獣医師の声を掲載（信頼性の基盤）
2. **SEO最適化**: 「犬 鑑別診断」「猫 病気 症状」等のキーワード対策
3. **コンテンツ戦略**: 月2本の疾患解説記事 → 専門性のアピールとSEO
4. **SNS展開**: X（Twitter）での症例クイズ、獣医コミュニティでの認知拡大

## 4. エンジニア（Engineer）の視点

### 総合評価: ★★★★☆（4.0 / 5.0）

### アーキテクチャ評価

**強み**:
- **シンプルで理解しやすい構成**: Flask + バニラJS。過度なフレームワーク依存を避けた堅実な設計
- **グレースフルデグラデーション**: 各モジュールのtry/exceptによるフォールバック。一部機能が使えなくてもアプリは動作継続
- **テストカバレッジ**: 101テストケースで主要機能をカバー。pytestベースで保守しやすい
- **RECO2/RECO3設計**: AI安全層のレイヤー分離（入力ゲート/出力ゲート/オーケストレータ）は優れたアーキテクチャ
- **セキュリティヘッダー**: CSP, HSTS, X-Frame-Options等の基本対策を実装
- **WCAG 2.1 AA準拠**: アクセシビリティへの配慮が設計段階から組み込まれている

**課題**:

| カテゴリ | 課題 | 重要度 | 推奨対策 |
|----------|------|--------|----------|
| **データ層** | ファイルベースDB（12MB JSON） | 高 | PostgreSQL/SQLiteへ移行。クエリ最適化とインデックス付与 |
| **フロントエンド** | 108KBの単一HTMLファイル | 高 | コンポーネント分割（Astro/Vite等）。コード分割とLazy Loading |
| **バックエンド** | 巨大Pythonモジュール（symptom_checker 485KB） | 中 | 責務分離。species_analyzerパターンのさらなる適用 |
| **スケーラビリティ** | シングルプロセスGunicorn | 中 | Workerプロセス設定、Redis等のキャッシュ層追加 |
| **CI/CD** | パイプライン未定義 | 中 | GitHub Actions: lint → test → deploy の自動化 |
| **モニタリング** | 本番監視なし | 中 | Sentry/DataDog等によるエラー追跡・パフォーマンス監視 |
| **API設計** | バージョニングなし | 低 | `/api/v1/` プレフィクスの導入 |

### セキュリティ評価

- **良好**: CORS設定、レート制限、セキュリティヘッダー、入力バリデーション
- **要注意**: `secret_key`のフォールバック値（`dev-key-change-me`）が本番で使用されるリスク → 環境変数の必須化を推奨
- **未評価**: SQLインジェクション（現在DBなし）、SSRF、依存パッケージの脆弱性スキャン

VetDictは技術的に優れた基盤を持ち、獣医学領域で唯一無二のポジションにある。最大の課題はマーケティング・ブランディングの不足であり、プロダクトの価値を外部に伝える仕組みを整備することで、大きな成長ポテンシャルがある。
