## 0. データ格納形式（確定事項 — 実測で確認済み）

> 実装前に確認が求められていた最重要項目。結論：**Postgres でも 静的Markdown でもない。**

VetDict の疾患データは **3層** で構成される：

| 層 | 実体 | 役割 | 永続性 |
|---|---|---|---|
| **① ソース・オブ・トゥルース** | `api/species/{species}_diseases.py` の `DISEASES: List[Dict]`（馬のみ `DISEASE_DATABASE` = dataclass） | 疾患レコード本体。全フィールドの一次情報 | git 永続 |
| **② オーバーレイ** | `diseases_all_species.json`（ルート, 6,449件）＋ `api/data/supplementary_diseases.json` | ①へ実行時に上書き適用（`helpers.enrich_diseases`）。低メモリ本番はこれで配信 | git 永続 |
| **③ 配信ビュー** | `instance/vetdict.db`（SQLite, `scripts/migrate_to_sqlite.py` が生成） | ①②を結合し検索最適化。低メモリ本番(512MB)では**ビルドをスキップ**し①②から直接配信 | **一時的・再生成される** |

**レコードのフィールド**（degu 実測）：
`name`, `name_ja`, `symptoms`(set), `urgency`, `recommended_tests`(list),
`description`/`_ja`, `causes`/`_ja`, `pathophysiology`/`_ja`, `treatment`/`_ja`,
`prevention`/`_ja`, `prognosis`/`_ja`, `onset_pattern`(set), `age_predisposition`(set)。

**現状にない**：`canonical_id`, `status`, `merged_reason`, `aliases`, `evidence_grade`。

### この確定がSPECに与える影響（重要）

1. **検出器は ①②③ のどれを読むか** → 「ユーザーが実際に見る配信ビュー」を忠実に読むため、
   `helpers.enrich_diseases()` + `dedupe_disease_list()` を通した **配信ビュー**を対象にする
   （SQLite未ビルドでも①②から再現可能。degu で 199件 = 現地観測と一致）。

2. **論理統合(canonical_id/status)の保存先は SQLite ではなく永続サイドカー**。
   SQLite は再生成・本番スキップされるため `ADD COLUMN` は消える。よって
   **`api/data/canonical_map.json`（git永続）に canonical_id / status / aliases / merged_reason を保存**し、
   `enrich_diseases` と `migrate_to_sqlite` の両経路で適用する。SPECの「ADD COLUMN のみ」は
   SQLite に対しては**適用しない**（永続層はJSONサイドカー、SQLiteは派生ビューとして再構築）。

3. **物理削除しない**要件は自然に満たせる：ソース①のレコードは無改変、統合はサイドカー②'で表現。

## 2. 非機能要件

- 全スクリプト**冪等**（複数回実行で同結果）。
- 改変前に対象を `backups/YYYY-MM-DD-HHMM/` へダンプ（ソース①のコピー＋サイドカーのコピー）。
- 論理統合/投与量公開は**1動物種 or 1カテゴリ単位**でバッチ提示→承認。
- 自動公開しない（🔴は全て人間承認ゲート）。

## 3. 失敗時挙動（自動停止条件）

- 検出フラグが想定の10倍超／統合で件数が想定外に激変／投与量ドラフトの出典が過半引けない
  → **自動実行を止めて Kentaro に報告**。

## 4. 訴求軸の転換（決定事項）

「7,000疾患」を誇らず「**臨床的に独立した実疾患・全て獣医師レビュー済み**」を軸にする。
NMNは残すが治療プロトコルから分離し「**自社製品・PR**」と明示（標準治療との誤認防止）。

## 5. degu パイロット実測（T101/T102/T104, 読み取り専用）

`reports/quality/degu-*.md` 参照。SPEC元票の仮説を実データで裏付け：

- **T101 完全重複 40件 / 20クラスタ**：`（デグー）`サフィックス付き重複（熱中症×2, 不正咬合×2,
  卵巣嚢胞 単複違い×2, バーバリング/毛引き×2, 消化管うっ滞×2 …）。既存 dedupe を
  サフィックス差異ですり抜けている。
- **T101 分割ファミリー**：`糖尿病` ×7（糖尿病/DKA/白内障/神経障害/網膜症/腎症/足潰瘍）。
- **T102 非臨床 5件**：糖尿病性神経障害・網膜症・腎症・足潰瘍（ヒト医学移植）＋アルツハイマー様疾患（研究モデル）。
- **T104 投与量なし治療 41件**（JA完全空0, 日英とも投与量なし20）。「見出しだけ」を裏付け。

→ **degu 199件の実体は概ね 130-150件**（40重複統合＋5非臨床アーカイブ後）。元票「50-80」は
  さらに分割ファミリーの臨床統合を含んだ見立てで、T103のレビュー段で個別判断する。
