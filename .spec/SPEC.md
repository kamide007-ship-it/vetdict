# SPEC — VetDict 品質改善（確定版）

Status: **データ格納形式 確定済み**（`.spec/DATA_MODEL.md` 参照）。実装は承認ゲート制。

## 背景・訴求軸の転換（決定事項）
実地検証（デグー疾患DB）で、疾患数が重複・分割・ヒト医学移植・研究モデル混入で
膨張していることが判明（degu 実測 201 → 実質50-80）。治療は見出しのみで投与量欠落、
出典はキーワード自動マッチ。
- 訴求を「7,000疾患」から **「臨床的に独立した実疾患・全て獣医師レビュー済み」** へ。
- 治療投与量は **必ず出典付き・公開前に獣医師（Kentaro）レビュー・自動公開しない。**
- 自社NMNブロックは **残すが「自社製品・PR」ラベルで標準治療から分離。**

## 機能要件
| ID | 要件 | リスク |
|---|---|---|
| T101 | 重複/分割 検出器：疾患名を正規化しクラスタ抽出（読み取り専用・レポート） | 🟢 |
| T102 | 非臨床エントリ 検出器：研究モデル/ヒト医学移植を辞書照合でフラグ | 🟢 |
| T104 | 空治療セクション 検出器：投与量パターン(mg/kg等)欠落ページを抽出 | 🟢 |
| T108 | 出典整合性 検出器：疾患カテゴリと出典/薬品リンクの不整合を検出 | 🟢 |
| T109 | 機械翻訳臭 検出器：置換辞書候補を抽出（葡萄糖→ブドウ糖 等） | 🟢 |
| T103 | 論理統合：`canonical_id`+`status` で非破壊統合、旧URLリダイレクト | 🔴 |
| T105 | 治療ドラフト生成：出典付き投与量を `draft` で生成（公開しない） | 🟡 |
| T106 | 投与量レビュー公開：獣医師承認後のみ `published` | 🔴 |
| T107 | NMNブロックのラベル化：残置しつつ「自社製品・PR」枠へ分離 | 🟡 |
| T110 | 出典紐付けv2：キーワード自動マッチ廃止、疾患単位キュレーション（v1残置） | 🟡 |

🟢=読み取り専用・自由実行可 / 🟡=改変だが可逆・バックアップ必須 / 🔴=承認まで実行禁止

## 非機能要件
- 全スクリプト冪等（複数回実行で同結果）。検出器は完全に副作用なし。
- 改変前に `backups/YYYY-MM-DD-HHMM/` へ対象をダンプ（`.py`/JSON/SQLite）。
- マイグレーションは **ADD COLUMN のみ**、`schema_migrations` で管理。物理削除禁止。
- 統合・削除・投与量公開は **1動物種/1カテゴリ単位でバッチ提示→承認**。

## データ構造（確定 — 詳細は DATA_MODEL.md）
- 格納形式：**静的 Python モジュール + JSON オーバーレイ + 派生SQLite**（Postgres無し）。
- degu は JSON オーバーレイに無いため **モジュール `.py` が配信実体**。
- ID は位置依存（`degu_0000`…）。**論理統合の前提として不変IDの付与が必要。**
- 追加カラム：`canonical_id, status, merged_into, merged_reason, aliases, evidence_grade, review_status`。

## 失敗時挙動（自動停止条件）
以下のいずれかで自動実行を止め Kentaro に報告:
- 検出フラグが想定の **10倍超**
- 統合で件数が想定外に激変
- 投与量ドラフトの出典が **過半引けない**

## 検証実績（degu 1種・T101/T102/T104 実行済み）
`.spec/DEGU_BASELINE.md` に全結果。要点:
- T101: 完全一致重複 **17クラスタ**（冗長17件）、疾患ファミリー候補 **30**（`diabet×11`, `catara×5` 等）
- T102: 非臨床 **3件**（糖尿病性網膜症・糖尿病性足潰瘍＝ヒト医学移植、アルツハイマー様疾患＝研究モデル）
- T104: 投与量なし治療 **26/201**、投与量あり 175、完全空 0
- いずれも失敗条件（10倍超）に非該当 → **想定範囲内。手動検証と一致。**
